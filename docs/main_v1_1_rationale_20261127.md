# main_v1.1の狙いと追加学習方針の妥当性

2026年11月27日。対象はAの既存3 seedで、E・A_main_v1.0・A_main_v1.1を比較する。v1.1は通常航法への不要な干渉を減らす追加学習版とし、Actor操作の平滑化は将来課題に分ける。

結論として、この狙いは合理的である。v1.0で確認された接近予防を残しながら、回避が不要な条件で観測された迂回・減速を修正するため、研究目的と問題の現れ方が対応している。ただし、経験追加が効く原因を特定済みとは扱わない。学習量、経験分布、Criticの評価、現在の報酬との整合を区別し、小規模な診断から段階的に進める。

## 観測から直接支持される問題設定

既存の共通48形状の対応比較では、AはEに対して機体平均到着時間が約1.3%増えた一方、未割引距離Costが約27.6%、純HOCBF補正秒/UAVが約26.4%減った。N2では距離Cost約91.7%減、割引純介入Cost約79.2%減、機体平均到着時間約0.7%増だった。N2の少数の厳しい遭遇の寄与は大きいが、N2を分けても初期CPA<30mペアの20m未満接近率はE38.89%からA25.31%へ減少した。したがって、予防的回避という既存の価値を維持することには根拠がある。

一方、全Nで通常QP解なしはA126機体tick・14episode、E0であり、介入負担と可解性の全面的な改善は示されていない。

ユーザー提示の追加診断では、実加速度ノルムや二乗加速度積分がAで大きく、初期候補ゼロ・実飛行でも90m以上離隔・HOCBF補正ゼロの機体に迂回と到着遅れがあった。また、他機の到着後に残距離30m以上ある単独区間でも補正・減速が残った。この条件では、少なくとも他機との接近回避を目的にした継続操作という説明は難しい。新しい航法経験を補って調べる対象として妥当である。提示された実運動診断の集計ファイル・重み付け・検出条件は、既存主比較の出典とは区別してNotebookに記録する。

ただし、A全体の加速度が大きいという平均だけで、全操作を不要と判定しない。必要な予防操作と不要な通常操作を分けて評価する。

## Referenceを通常航法の比較相手とする理由

通常航法をReference、接近を見越した変更を残差Actor、最終的な安全補正をHOCBFが担当する構成である。回避が不要な条件でReferenceに近い効率へ戻す狙いは、この役割分担と整合する。

目標はReferenceへの完全一致でも、全状態で残差ゼロでもない。Actorが安全に到達効率を改善する操作は残してよい。Referenceより遅く、より迂回し、接近回避にも寄与しない操作を減らせるかが中心となる。

## 追加する経験と仮説の対応

| 経験 | 合理的な役割 | 検証上の限界 |
| --- | --- | --- |
| 単機のReferenceとActorの実軌道 | 他機の影響を除き、通常航法での行動価値を学ぶ | 単機での改善が多機体へそのまま移るとは限らない |
| 初期CPAが全ペア75m以上の複数機 | 複数機が存在しても不要な変更を抑え、Actorが作る接近を学ぶ | 初期CPAの分類はActor操作後の非接近を保証しない |
| 従来の接近経験と新しい接近軌道 | 通常航法の修正中も、予防的回避を学ぶ機会を残す | 混ぜるだけで忘却しないとは保証できない |

この3種類は相互補完的で、単機だけの追加より合理的である。単機データにも方向・距離・初速・機体能力の幅を持たせ、特定方向の直線を暗記した結果にしない。生成・収集量は先に上限を決め、非接近条件を満たす形状が集まらない場合は、生成条件や対象Nの見直しを明示する。

Reference軌道も実際に収集し、元のActor軌道の操作だけをゼロへ差し替えた架空の遷移は作らない。安全処理と報酬算定は通常と同じ構成で実行する。

## 現在の報酬で改善を期待できる条件

現行設定には進捗報酬、毎tickの時間ペナルティ、正規化残差二乗のペナルティがある。通常航法で余計な遅れや残差が不利になる仕組みは既にあり、報酬を変えずに経験と価値推定を修正する試みには根拠がある。

ただし、実加速度二乗積分や加速度変化を直接最小化する目的ではない。想定する原因は次の3系統に分ける。

1. 現行目的の下でも良い通常航法へ到達していない。学習量や経験分布の不足が候補となる。
2. より良い操作の価値をCriticが適切に評価できず、Actorへ伝わっていない。
3. 研究上望む航法が、現行の割引・進捗・残差・エントロピーを含む学習目的では十分に有利になっていない。

学習開始前に、同じ単機条件のReferenceとA_v1.0について、実際の学習定義と同じ報酬項・割引でreturnを比較する。Referenceのreturnが良く、それをCriticが評価できていないなら、価値推定修正を狙う直接的な根拠になる。Criticが正しく評価していてActorが従わないなら、Actor最適化・探索・エントロピーの寄与も調べる。

SACのReward Criticはエントロピーを含むsoft targetを使うため、生の環境報酬returnだけでQの誤りを断定しない。Referenceで最後まで飛んだreturnは、以降Actorへ従うQ(s,残差ゼロ)の正解ではない。Criticの行動順位を確認する場合は、同じ状態・継続方策・Actorの保持周期と位相・エントロピーの扱いをそろえる。

Referenceの方が時間・操作負担では良くても現在の目的値では不利なら、経験を増やすだけで直るとは限らない。まず現行定義で検証し、報酬や制御則を変える場合は別の実験変更として識別する。

## Critic修正を先行させる合理性

v1.0が偏った価値推定を持つ場合、同じCriticでActorだけを更新すると、その評価を強化する可能性がある。Actorを固定して新しい経験へCriticを適応させてからActorを更新する順序は、その懸念に対応する。

一方、偏りを確認する前から「Criticが原因」と確定しない。Critic修正段階ではActor・λ・αを固定し、損失低下だけでなく別形状での価値診断を見る。Actor固定では飛行挙動は改善しないので、この段階の成功を航法改善とは呼ばない。修正量を増やし続けると限られたデータへの過適合も起こり得るため、update数と終了基準を先に決める。

単機ではReward Criticとそのtargetだけを更新する方針は、単機領域の不確かなCost推定をActorへ作用させず、通常航法の報酬側を調べる切り分けとして合理的である。ただし「単機のCostが定義上ゼロ」と「単機でCost Criticを学習させることが常に誤り」は同義ではない。今回はCost側を変える範囲を抑える実験上の選択として扱う。

現行backendはReward/Cost Criticとtargetをまとめて更新する構造なので、損失・optimizer状態・target更新・Actor側Cost項の除外を明示的に制御し、不変性を確認する必要がある。

## 固定λで切り分けられるもの

seedごとのv1.0最終λを固定することで、追加学習中の双対変数の再調整を除外できる。安全制約の係数を意図的に強め直す実験とは区別しやすい。

ただし現行の実効CAL係数はmax(0, λ+c×開始状態Cost推定の予算超過)である。Cost Critic・Actorが変われば係数も変わり、λ=0でも必ずゼロとは限らない。固定λはCost項全体の固定でも制約達成の保証でもない。報酬・Cost・予算・CAL係数を維持し、実効係数と実測安全指標を追う。

学習Replayを容易な条件へ広げることと、制約を評価する開始分布を変えることは分ける。今回は制約の基準を維持するため、CALの開始分布はv1.0のものを保つ。v1.1では単機Actor更新でCost項を外し、学習データ分布も広げるため、v1.0と完全に同じCMDPの単純な延長ではなく、対象を絞った追加学習として説明する。

## 比較から主張できる範囲

E・A_v1.0・A_v1.1の共通条件比較により、v1.1という追加学習全体が通常航法を改善し、接近予防を維持できたかは評価できる。

しかし、この3者だけでは、追加学習量、経験追加、Critic先行修正、λ固定の個別の因果効果までは分離できない。そこまで主張する場合に限り、同じ追加学習量と固定λで従来経験だけを使う継続対照などを追加する。初回から大きな比較網を作らず、まず3者で実用上の改善を確認する方針でよい。

通常航法では到着時間・経路長・横/高度逸脱・単独区間の負方向補正・実加速度と二乗加速度積分を見る。接近条件では初期CPA別の最近接距離・20m未満接近率・最終離隔・純補正時間/強度・QP可解性/fallbackを見る。効率改善だけで成功とせず、接近予防の維持を同時に判定する。

性能維持は、悪化の有意差が出なかったことだけでは証明しない。許容悪化幅と評価量は追加学習前に定める。モデル選択に使ったbankを最終未使用testと呼ばず、固定した別形状で確認する。

## 平滑化を将来課題へ分ける理由

不要な操作を減らすことは「どの状態でどれだけ航法を変えるべきか」の問題であり、指令を滑らかにすることは「時間方向にどう変化させるか」の問題である。前者が改善しても後者が改善するとは限らない。

v1.1に平滑化フィルタ、加速度変化ペナルティ、Actor更新周期変更まで加えると、航法経験の追加による効果と制御応答の変更が混ざる。このため、平滑化を将来課題へ分けるのは合理的である。将来は急変の低減だけでなく、必要な回避の遅れやHOCBFとの整合も検証する。QP可解性や最終離隔の悪化は平滑化と別の安全問題なので、v1.1でも確認を続ける。

## 実行前に決める最小事項

- 旧Replayを含むfull_resumeが使えるか。model_onlyからの分岐なら旧経験の用意方法を区別する。
- 3種の経験の量とサンプリング比率、Critic修正update数、追加online step、評価と停止の間隔。
- Actor学習時のαの扱い。現時点ではv1.0から継承し、従来の自動調整を維持する案。
- 共通評価bank、接近予防を維持したと判断する許容幅、版・親hash・段階別の保存先。

学習・Replay・評価形状の量は初回から大きくせず、報酬整合性の診断、短いCritic修正とActor追加学習、小規模共通評価の順に進める。改善が見えた段階で、必要な範囲だけ学習と評価を追加する。
